# Modern House OMS 1.2.0 implementation plan

**Goal:** Fix logout/re-login, require chosen local admin credentials, let the customer choose local DB storage during first-run setup after installation, and provide optional authenticated read-only remote viewing with the server supplied later.

**Architecture:** SQLite remains authoritative and local. A control config in the existing userData directory points to a selected local DB directory. Existing data migrates only into an empty selected target; old files are retained. The desktop session starts locked, and first-run setup creates hashed admin credentials. Optional HTTPS snapshot publishing is handled in Electron main; renderer network access stays disabled. A separate deployable read-only server accepts authenticated snapshots and serves a password-protected dashboard.

**Tech stack:** Existing Electron/React/TypeScript/Node SQLite and NSIS; Node built-ins for HTTPS connector and companion server.

## Delegated ownership

1. Auth: `contexts/AppContext.tsx`, `screens/WebsiteScreen.tsx`, `src/desktop/localService.ts`, `src/desktop/build.mjs`, focused auth tests. Confirm and fix duplicate module/listener IDs, remove anonymous login bypass, stop logged-out subscriptions and ignore stale async session work.
2. Setup/storage: `database.cjs` and tests, `installation.cjs` and tests. APIs: `hasLocalAdminCredentials`, `setLocalAdminCredentials`, username/email `login`; `createInstallation({controlDirectory})` exposes database/dataDirectory, status/configure/close. Keep backup format/schema compatible, protect an already-configured account from anonymous reset, migrate data safely.
3. Remote: `remote.cjs` and tests plus `remote-server/*`. Encrypted tokens through injected safeStorage; HTTPS only, verified TLS, timeout/size limits, no credentials/users in snapshots. No default external endpoint. Server requires separate upload token and browser credentials and has no editing routes.

## Root integration

- Add a desktop access/setup screen shown when there is no authenticated user. Form asks username, password/confirmation, and directory via native folder picker. First-run setup opens after the installer finishes and applies equally to portable startup.
- Start with no active session; guard data and remote IPC with session/admin checks. Remove localAdmin bypass; logout must lock subsequent CRUD immediately. Keep initial theme/language bootstrap usable.
- Restart backup manager after first-run directory migration, and use selected dataDirectory for DB/backups/open-folder.
- Add local-data status and external-server controls in Settings. Remote publishing is opt-in per server, manual plus dirty snapshots every five minutes after explicit enablement. No server is configured or contacted during this task.
- Add packaged tests for setup/username-password/login/logout/re-login/access denial, custom-directory migration, existing transactions/backups, remote loopback tests, and legacy data compatibility.
- Build version 1.2.0 installer/portable, inspect payload and verify execution with isolated profiles. Preserve existing installation and previous release files.

## Delivery limits

User chose: prepare the connector; server details will be provided later. Deliver the server package and deployment instructions; do not claim it is deployed or reachable on the internet. Do not expose SQLite directly or include actual user data, credentials or server tokens in release files.

# Modern House OMS 1.1.0 Implementation Plan

**Goal:** Deliver an offline Windows x64 EXE installer with faster record updates, atomic stock workflows, periodic local backups and compatibility with version 1.0 data.

**Architecture:** Preserve Electron, React and the existing SQLite records/preferences schema and backup format. Add domain operations to LocalDatabase and expose them through the existing trusted IPC bridge. Put backup scheduling/retention in a separately tested module. Build in this isolated source copy, preserving the original app and real user data.

**Tech Stack:** Electron 44.4.5, Node SQLite, React 19, TypeScript, Vite 6, electron-builder 26.15.3 / NSIS.

## Scope and decisions

- Keep appId `bh.modernhouse.oms.desktop`, `%APPDATA%\ModernHouseOMS`, schema and backup format version 1.
- Release version 1.1.0; independent installer contains no customer/user business data and needs no Node installation.
- Optimize update lookups using the `(collection,id)` primary key, preserving password hashes internally and public hash filtering.
- Commit an order and its aggregated stock deltas, optional delivery/notifications and request/quotation conversion in one `BEGIN IMMEDIATE` transaction. Update/delete use stored order data rather than stale UI snapshots.
- Receive purchase orders atomically and only once.
- Save automatic backups at startup, after changes every 15 minutes, and on normal shutdown; retain bounded recent snapshots and daily files. Report automatic backup failures without losing manual export.
- Keep existing collection subscription API. Paging all screens is deferred because it would require a wider UI/data-provider change; direct updates and transactions are the concrete improvements in this release.
- Preserve browser/cloud behavior outside the desktop-specific branches.

## Task 1: Database (delegated)

Files: `src/desktop/database.cjs`, `src/desktop/database.test.cjs`.

1. Write failing tests for atomic order save/update/delete, rollback, repeated product IDs, insufficient/invalid stock inputs, custom quotation items and receiving a PO only once.
2. Test direct record update without scanning the collection and preservation of credential hashes.
3. Implement `saveOrder(order, {id?,deliveryOption?,requestId?,quotationId?,userId?})`, `deleteOrder(id)`, `receivePurchaseOrder(id)` and indexed internal lookup.
4. Verify Node tests and legacy backup compatibility.

## Task 2: Backups (delegated)

Files: `src/desktop/backups.cjs`, `src/desktop/backups.test.cjs`.

1. Write failing tests with a controllable clock/timer for dirty snapshots, no redundant idle snapshots, retention, failure handling and close flush.
2. Implement a backup manager with atomic temp-file rename, 15-minute dirty snapshots, daily history and normal-close flush.
3. Export integration API documented for main.cjs; root integrates it.

## Task 3: Renderer workflows (delegated)

Files: `contexts/AppContext.tsx`, `screens/POSScreen.tsx`, relevant focused tests.

1. Route local create/update/delete order and receive PO actions to one IPC domain call each.
2. Include request/quotation conversion options; prevent a duplicate conversion when an order is already linked.
3. Print the actual saved local order/number instead of a newly synthesized order number.
4. Test behavior through focused integration tests or packaged smoke assertions; keep cloud fallbacks.

## Task 4: Runtime integration and packaging

Files: `src/desktop/main.cjs`, `src/desktop/package.json`, root `package.json`, `src/desktop/README-AR.md` and release instructions.

1. Integrate domain IPC calls, emit affected collection events after commit and mark backup state dirty after successful writes/preferences/restores.
2. Start backup timer after opening the DB; flush before DB close and show meaningful backup failure feedback.
3. Extend isolated packaged smoke test to cover atomic operations and automatic backups.
4. Bump version, include new runtime modules in the packaging whitelist and enable correct product metadata without signing.
5. Run unit tests, TypeScript checks on touched code, offline renderer build and NSIS packaging.
6. Test the packaged executable twice with isolated userData and a legacy-data fixture; inspect installer contents/metadata. Never smoke-install the production appId over the current installation. If installer execution is tested locally, use a distinct QA appId/GUID and disposable directory with automatic launch disabled, then uninstall that QA package.
7. Deliver `Modern-House-OMS-Setup-1.1.0.exe`, a checksum, concise Arabic install/migration instructions and source changes. A new PC starts with an empty local DB; data moves only via explicit backup/restore.
